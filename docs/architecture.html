Architecture

The current architecture, extending the base. Browser → Next.js web → NestJS BFF → upstream catalog + content. Run a scenario to watch a request travel, change the upstream conditions to see how the BFF reacts, or click a box for details.

Upstream conditions

Simulation of GET /api/products. Real-run equivalents: UPSTREAM_LATENCY_MS (applies to both services), UPSTREAM_FAIL_SERVICE=catalog|content, and the BFF's UPSTREAM_TIMEOUT_MS. A request that takes longer than the timeout is aborted and counts as a failure of that service.

Scenarios

The cart scenarios (Add to cart, Refresh) stay in the browser: there is no cart endpoint, so no request reaches the BFF. View cart is the one exception: /cart fetches /api/products server-side to price the lines, so it honours the latency and failure controls above. All share one simulated cart, capped at 10.

Animation time is compressed; the log and timeline show the simulated milliseconds.
